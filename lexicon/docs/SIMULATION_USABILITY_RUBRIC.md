# 模擬使用者易用性評估（常態卡 #12）

模擬不只找闕漏／錯誤，更要思考學習者覺得方便、需要什麼。

## 評分面向（每輪都要過一遍）

1. **方便**：完成常見動作要幾步、幾次點擊？有沒有多餘畫面？
2. **必要**：畫面上的每一塊資訊對「學這個字」有沒有幫助？沒有就建議拿掉或收到次要入口。
3. **一目了然**：卡片背面／詳情能否掃一眼抓住單字重點（意思、發音、例句）？
4. **雜訊**：來源、授權字串、編號、頻率、內部 id、除錯字樣不應出現在學習主路徑（尤其卡片背面）。授權若必須保留，改成長按／資訊頁。
5. **清晰**：用詞是否像給人看的說明，而不是工程日誌。

## 產出

- 每輪至少 1–3 個**具體** UX 改善建議（寫得出「哪個畫面、拿掉／改成什麼」）。
- 沒有重複就開問題回報（`reporter=claude-simulation`），附輪次與畫面。
- 明顯小錯可直接修並補測試；要改規格或資料的先記成待決定。
